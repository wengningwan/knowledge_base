# OXR 解析验收

本页供部署维护者在测试环境验收 OXR 解析。前置条件是正常运行的 API、worker、PostgreSQL、MinIO、Milvus 和所需模型，配置方法见[文档处理与 OCR](document-processing.md)。目标是核对真实产物与失败边界；此清单不代表这些检查已经通过。

1. 运行项目既有存储迁移流程，使 knowledge schema 升级到 3，再启动 API/worker。旧文件的正文指针和状态应保留，新增解析字段为空。
2. 在设置中确认默认 OCR 选择保持原值。配置 OXR 免费地址或自建地址，分别选择或清空图片解析和正文校对模型，上传同一篇论文。
3. 对照原 PDF 检查标题、双栏阅读顺序、跨页续句、四个公式及式号、化学表达、上下标、数字单位、文献引用、图片位置和原文图注。下载 MD 不应含解析提示、图片模型说明或校对报告；图片与 HTML 表格内图片应能离线显示。
4. 在图片解析和校对标签确认模型来源、未启用/失败/未决状态、关键修订和原文区域。遗漏原生正文或页覆盖不足时不能显示全部校对完成。两个模型同时清空仍应完成主解析。
5. 对已入库文件重新解析，成功后应回到 parsed，旧 chunks/向量/图谱和统计已清理，再手动入库。模拟解析失败时应显示上一版结果；普通重试成功同样清理旧索引。
6. 验证取消、重试、worker失去lease、整库删除和图谱构建互斥，确认不会发布旧执行结果或丢失已知远端任务编号。测试删除失败后重试，确认全部 attempt 资源可清理且文件元数据保留到清理成功。
7. 使用另一个无权限账号请求正文、图片和 parse-assets，确认拒绝。切换文件及关闭弹窗后，旧异步响应不得串到新文档。

本机准备的协议、单元、真实 PG 和 HTTP 集成用例尚未执行。命令与运行前置由[测试规范](../develop-guides/testing-guidelines.md)拥有；部署验收还需检查免费服务可用性、模型响应、Vue 编译和目标论文的视觉结果。
