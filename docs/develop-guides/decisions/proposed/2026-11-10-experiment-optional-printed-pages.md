# 实验证据保留 PDF 页码并显式报告缺失的印刷页码

状态：proposed
类型：bug-fix
Owner：backend/package/yuxi/knowledge/structure.py

## 问题

实验卡片在论文登记阶段返回后要求整份 PDF 都有数字印刷页标，或首页存在覆盖全文的连续期刊页范围。没有完整映射时任务失败，已经定位到 PDF 物理页的实验证据也无法发布。用户提供的失败日志显示，模型返回后触发此限制；日志不包含原 PDF，无法确认原件是否印有可提取的页脚。

目标是让具有可核对 PDF 页码的实验记录继续生成，并明确表达未知的印刷页码。假设实验出处以原 PDF 物理页和冻结正文为核对基础，印刷页码是可缺失的补充信息。范围只覆盖页码映射、对应 JSON 字段和当前行为说明；不添加 OCR 页脚识别、不猜补期刊页码、不改变题录与证据校验、模型额度、任务发布或人工审核。

## 提案

### 实现方案

抽取模块继续从同一 PDF 和冻结正文建立物理页证据。首页期刊页范围与标题一致、覆盖全文且不与明确页标冲突时生成完整映射；否则仅保留 PDF 中明确记录的数字页标。范围与页标冲突写入校验说明，禁止利用冲突范围补齐其余页。

[JSON 契约](../../../../backend/package/yuxi/knowledge/adsorption_schema.json)允许证据的 `printed_page` 为正整数或 `null`，字段仍为必填；`pdf_page` 继续要求正整数，`pdf_page_to_printed_page` 仅包含已核对的映射。存在未知印刷页码时记录 `unverified_printed_pages` 警告，通过现有 `validation_issues`、覆盖摘要和页面的部分完成状态提供可观察结果。页码说明使用独立编号前缀，在工作台的原文疑点中阅读；程序剔除候选的说明继续归入程序跳过。模型题录中的 `pages` 保留原文页范围或文章编号，未报告时使用空字符串。

字段扩展保留当前 draft 格式和既有整数数据，已有 JSON 继续下载。仅推进抽取提示版本，使重新入库能够生成新的结果；不修改持久化 schema 版本或已有草稿。[实验面板](../../../../web/src/components/knowledge/ExperimentCardsPanel.vue)对规范 JSON 和旧草稿共同显示已有的部分完成提示。出处继续按 PDF 页码定位，印刷页码有值时补充展示，页码警告使用中文标签。

本记录修正[规范 JSON 提案](2026-11-09-canonical-adsorption-output.md)中缺少可核对印刷页码即整篇失败的验收预期；题录、物理页证据与最终完整契约校验继续保留。

## 替代方案

保留硬失败能维持每条出处都有印刷页码，但会拒绝未正式编页、只有文章编号或缺少 PDF 页标的论文。把物理页码填入印刷页字段会伪造出处。增加页脚识别需要更多原件样本及误识别边界；当前缺少这些证据，且不影响已有物理页定位能力。

## 风险

外部 JSON 消费者需要接受 `printed_page: null`，下载格式仍处于 draft。当前仓库的页面已按有值条件展示印刷页码；没有可核对印刷页码的记录仍需用户通过 PDF 物理页核对。原始论文、真实 provider、worker、PostgreSQL、对象产物、浏览器和静态 gate 均需在部署电脑验证；源码审阅不能证明这些结果。
