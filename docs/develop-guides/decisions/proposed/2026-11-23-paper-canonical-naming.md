# 论文结构化导出使用通用格式名称

状态：proposed
类型：bug-fix
Owner：backend/package/yuxi/knowledge/adsorption_schema.json

## 问题

Paper 结构化可以记录不同学科的实验。格式标识、根记录编号、下载文件名和错误消息沿用[最初的吸附分离提案](2026-11-09-canonical-adsorption-output.md)的领域用语。工作台的默认分类称为材料性质，部分方法标签还带入样例特有的试剂或工序，容易误导对通用数据的解读。

## 提案

### 实现方案

Worker 为新草稿写入 `paper-canonical`，以 `paper:` 为根记录编号前缀，并通过通用阶段名称记录调用。JSON Schema 同时识别新旧格式标识，格式版本和已发布草稿所用的内部版本继续兼容。重新入库按新版提取标记生成新草稿。读取继续返回原 revision，保留存量根编号、关联与校对回执。

工作台的下载文件名统一为 `paper-structure-<文件编号>.json`。搜索提示使用样品、指标和数值等通用词。未归类的测量使用通用名称，领域专属名称只用于有明确对应含义的类型。

## 替代方案

仅改文件名会保留 JSON 中的误导标识。批量改写历史编号需要同步替换同草稿内的引用，还会改变用户已有的导出对接。根据论文主题切换格式标识会让同一种契约产生多个名称。

## 验收标准

| 验收主张 | 失败面 | 语义 Owner | 直接证据 / 命令 | 负向案例 | 当前结果 |
| --- | --- | --- | --- | --- | --- |
| 新结构化统一使用通用名称 | 光催化或其他论文仍带吸附前缀，或新根编号的引用不一致 | Worker 和 JSON Schema | 部署电脑用 Paper 生成论文草稿，打开原始 JSON 并下载，核对格式标识、根编号、关联、任务日志和文件名 | 将新导出的 `schema_id` 改为未登记的值，按项目 JSON Schema 校验时应拒绝 | Not run |
| 旧草稿继续查看、审核和下载 | 格式改名使旧草稿不可见，或旧引用被读时改写 | 结构化读取用例及持久 revision | 打开已有草稿，核对原有卡片、校对回执及下载中的根编号与关联 | 通过 API 请求不匹配的 revision，仍拒绝返回旧正文的草稿 | Not run |
| 工作台如实描述测量和方法 | 普通测量被归为材料性质，或热处理被显示为炭化活化 | 实验工作台展示 | 在部署电脑查看光催化和已有吸附论文的测量筛选、搜索提示及类型标签 | 打开只有热处理信息的步骤，应只显示热处理 | Not run |

## 风险

外部脚本若按旧标识、根编号前缀或文件名匹配新导出，需要识别新名称。用户已下载的文件和已发布草稿保留原数据。本机仅静态检查，浏览器及 Worker 行为待部署验证。
