# 实验记录审核的具体校验提示

状态：proposed
类型：bug-fix
Owner：backend/package/yuxi/knowledge/experiment_review.py

## 问题

新增实验记录选择了不包含样品或结果的出处时，确认校验拒绝请求。审核路由将校验原因放在字符串 detail 中，前端统一请求层只接受带 code 和 message 的业务错误对象，因此编辑表单显示「请求参数错误」，用户无法知道需要修改哪个字段或出处。

目标是让管理者在审核失败时看到可采取行动的固定校验提示。假设现有新增确认规则继续生效；非目标是放宽原文定位、改变保存状态或修改通用错误脱敏规则。

## 提案

### 实现方案

实验审核字段契约和保存用例用专门的 ExperimentReviewValidationError 表达预期输入错误，异常消息只使用固定业务文案。审核路由将该异常转换为 HTTP 400，detail 为 code/message 对象；现有前端请求层提取 message，编辑表单保留输入并显示原因。其他 ValueError 继续走通用错误提示，避免把存储或解析异常扩展为可展示信息。

字段契约拥有出处与原文字面校验，保存用例拥有记录、片段和校对任务的输入约束，路由拥有 HTTP 错误装配，前端统一请求层拥有可展示错误对象的读取。权限、正文与审核版本检查、持久化事务和机器 JSON 保持现有语义。

## 替代方案

- 所有 HTTP 400 直接展示字符串 detail：改变全局脱敏边界，可能展示底层异常或敏感输入。
- 审核路由包装所有 ValueError：无法区分预期业务拒绝和正文读取等底层错误。
- 专门异常与现有业务错误对象：只展示明确由审核规则产生的固定原因，复用已有前端消费路径。

## 验收标准

| 验收主张 | 失败面 | 语义 Owner | 直接证据 / 命令 | 负向案例 | 当前结果 |
|---|---|---|---|---|---|
| 确认失败显示具体样品或结果校验原因 | 页面只显示通用参数错误，或错误确认成功 | 字段契约、审核路由和编辑表单 | 在部署机新增完整测量记录，先选择不含样品的引文，再选择包含样品但不含所填结果的引文；分别核对响应 detail.message、页面提示和重开后的记录状态 | 预期分别拒绝并提示找不到样品名、找不到操作或结果；人工版本不变且不产生 confirmed 记录 | Not run：本机不运行程序 |
| 其他预期输入错误同样可见 | 任务、记录或出处校验继续只显示通用错误 | 保存用例与审核路由 | 使用当前 revision 和版本提交未知记录 ID 或未知出处 ID，核对具体提示及未写入结果 | 未知记录和未知出处均拒绝，不能写入新人工记录 | Not run：本机不运行程序 |

| 可展示信息限定为固定审核校验文案 | 任意底层 ValueError 或 schema 输入被透传 | 专门异常、审核路由与前端统一请求层 | 审阅全部专门异常产生点及 catch 顺序，核对前端只读取业务错误对象 | 非业务 ValueError 保持字符串 detail，422 仍使用通用校验提示，前端不展示底层原始信息 | Inspected：专门异常产生点均为固定文案，路由单独映射，前端只提取业务错误对象 |

## 风险

此修复改变审核 HTTP 400 的预期业务拒绝响应形态。新增异常只允许携带可直接展示的固定文案；后续新增产生点同样需要审查。真实 HTTP、浏览器提示及 PostgreSQL 回读由用户在部署电脑验证，本机不执行测试、构建或验证脚本。
