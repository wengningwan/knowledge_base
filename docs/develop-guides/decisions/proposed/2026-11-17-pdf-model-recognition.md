# PDF 增加模型逐页识别模式

状态：proposed

类型：feature

Owner：backend/package/yuxi/services/ocr_service.py

## 问题

用户需要在知识库 PDF 解析中选择 OCR 识别或模型识别。模型识别直接读取逐页原图，生成可追溯的全文 Markdown；OCR 识别继续使用现有引擎及适用的正文校对、插图说明。当前局部正文校对依赖前序解析已保留内容，无法据此保证恢复整段漏识别的正文。

当前 [统一入口](../../../../backend/package/yuxi/services/ocr_service.py)先解析 OCR 配置，[PDF 分发](../../../../backend/package/yuxi/knowledge/parser/unified.py)区分原生文字、OXR 和其他 OCR 引擎。本提案聚焦新增模型逐页识别分支，复用原有 OCR、正文校对和独立插图流程；正文校对的引擎适配范围暂不展开，也不作为新增模型识别模式的前置条件。

## 提案

### 范围和界面

首版覆盖知识库 PDF 的上传、解析、重新解析、失败重试和批量入口。聊天临时附件、工作区 OCR 工具、其他文件格式、自动拆分不同论文和曲线取点保持各自当前行为。本提案不承诺某个模型的准确率，也不指定供应商。

文件级 `pdf_parse_mode` 选择解析方式，缺省为 `ocr`。模型识别必须明确指定 `document_recognition_model`。表单沿用已有的正文校对模型默认值。模型识别任务的 `document_review_model` 缺失或留空时跳过模型校对。插图解析模型可留空。

| 模式 | 界面参数 | 生效规则 |
| --- | --- | --- |
| 模型识别 | 识别模型、可选的正文校对模型和插图解析模型 | 正文校对只读取原 PDF 页面图像，在合并前执行 |
| OCR 识别 | OCR 引擎、正文校对模型、插图解析模型 | 保留既有 OCR 及附属处理方式；正文校对模型、插图解析模型均可留空 |

OCR 引擎列表保留现有“不使用 OCR”选项及语义。切换模式只提交当前模式生效的字段，后端再次收敛有效参数。混合批次中的模型识别只作用于 PDF。非 PDF 文件的参数保存和读取均移除识别方式与识别模型字段。单文件解析表单从文档基本信息读取已保存的设置，并根据存储原文件的后缀显示识别方式。非 PDF 文件直接显示 OCR 设置。表单尚未取得默认引擎且文件未保存引擎时，省略 OCR 引擎字段，由服务端读取系统默认值。

### 实现方案

[应用服务入口](../../../../backend/package/yuxi/services/ocr_service.py)在 OCR 配置读取前识别 PDF 模式：模型模式校验所选模型存在、已启用且属于聊天模型，不读取 OCR 服务配置；OCR 模式保持现有分发。非 PDF 在运行时移除 PDF 模式与识别模型参数，再进入其原有解析器，避免混合批次中的图片误用 PDF 的模型分支规则。模型是否真正接受图像以实际供应商响应为准，现有前端图像能力提示不能替代后端调用结果，也不新建一套模型能力登记系统。

逐页识别用例落在新增的 `pdf_recognition_service.py`，模型返回值的解析和块归一落在新增的 `knowledge/parser/pdf_recognition.py`。渲染复用现有 [PDF 区域渲染](../../../../backend/package/yuxi/knowledge/parser/pdf_native.py)，PDFium 调用继续持有公共锁。真实页数由本次打开的 PDF 取得，页码由服务端分配；页面图像按现有尺寸上限生成，按有界队列渲染和识别，不预先把整本 PDF 的图像载入内存。

每个请求只读取一页原图，要求忠实转写中英文正文、标题、图注、表格和公式，按自然阅读顺序返回块数组。标题、正文、图注、表格、公式、插图及明确页眉页脚具有不同类型。插图提供有效的归一化位置，程序据此从原 PDF 裁图。图注作为独立正文块只渲染一次。模型能确定归属时，插图块通过可选的同页 `caption_index` 引用原文图注，归一器校验引用目标后将内容提供给插图解析。缺少明确归属的插图保留空图注，避免按相邻位置错配。表格保留可复制表体，插图及化学结构保留原图。

返回值包含“本页已输出完毕”的显式回执；检查 JSON 结构、已知类型、非空文本、合法位置和模型实际停止原因。[聊天适配器](../../../../backend/package/yuxi/models/chat.py)当前丢弃供应商停止原因，需要先以可选字段透传，再由文档执行器交给识别服务；供应商未提供时保持未知。截断、页级不完整、缺少必要字段、非法图片位置或无内容而未声明空白页均视为该页失败。空白页必须显式返回空白类型，不能用缺失结果代表空白。回执与结构校验仅证明处理协议完整，不能证明模型没有漏字、错字或错误判断空白页；这部分仍由原文人工核对裁决。

识别结果转换为现有 [ParsedDocument](../../../../backend/package/yuxi/knowledge/parser/result.py)，按物理页码与校对后的页内顺序合并。归一器把独立正文块设为 `paragraph_start=True`。确认过的跨页续接通过相邻页块的身份记录，渲染时保留两个源块。跨页表格保留各自的分段。 [正文渲染与资产替换](../../../../backend/package/yuxi/knowledge/parser/pdf_structure.py)

每条独立编号的反应式分别排版。发布模型识别正文或保存人工公式修改时，按块中已有的顶层 `\tag{数字}` 或独立行末的 `\qquad (数字)` 分开连续的反应式，公式字符、原编号及顺序照原样保存。已有对齐、分段及其他 LaTeX 环境按原组保留。将多个普通编号直接放进同一个数学块会触发预览排版错误。 [模型公式分块](../../../../backend/package/yuxi/knowledge/parser/pdf_recognition.py)

[文档组合](../../../../backend/package/yuxi/services/pdf_document_service.py)使用模型块确定插图身份、图注和阅读顺序。在同一页找到与模型图框相互覆盖至少一半的 PDF 内嵌图像时，合并两者的范围。插图区域从原页渲染，并在邻近块与页边界内留出余量，兼顾图像之外单独绘制的刻度、轴名和矢量内容。找不到相符的图像时，以模型框和同样的边缘余量渲染原页。插图解释由 [独立 Durable Task](../../../../backend/package/yuxi/services/knowledge_figure_analysis_service.py)发布到同一解析版本的附属结果。

逐页模型请求并发执行，复用 [共享请求执行器](../../../../backend/package/yuxi/services/pdf_model_execution.py)和现有 `document_model_concurrency` 配置；同一端点与模型在跨文件、跨 worker 的请求间共享槽位，不新增逐页并发配置。单篇文档同时处理的页数取总页数与阶段并发配置的较小值，完成顺序可以不同，最终始终按物理页码合并。调低共享并发时继续沿用现有准入规则，不打断已在途的请求。

单页模型请求不设置固定时限，也不新增请求超时参数或配置，沿用执行器不设请求时限的行为。任务取消、执行租约及现有任务生命周期控制继续生效。对暂时连接故障、供应商返回的超时和协议失败最多重试一次；凭据错误、服务拒绝图像或请求受限直接结束本文件识别，停止继续派发待办页并收敛在途请求，不自动切回 OCR、不自动换模型。

### 发布、状态与记录

任一页在有限重试后仍失败，整份新正文不发布，文件进入现有解析错误态；错误消息包含服务端页码、稳定原因与请求身份，排除供应商原始报错和文档正文。整份模型结果渲染后没有可用 Markdown 正文时也明确失败；论文内的单个空白页允许保留，整本空白或只有被排除出版块的文档不发布空正文。重新解析时原 Markdown 与附属结果的指针保持不变。模型识别完成前不启动独立插图任务、不清理旧索引。所有页面成功后，复用 [文件解析发布流程](../../../../backend/package/yuxi/knowledge/base.py)和 [产物保存](../../../../backend/package/yuxi/services/knowledge_parse_service.py)生成同一次 attempt 的 `document.md`、`assets.json` 与图片；成功发布的 owning transaction 提交后再投递插图任务。成功重新解析继续清理旧分块、向量与图谱，回到待入库状态。

`assets.json` 的 `metadata.model_recognition` 保存模型、提示词版本、总页数、各页状态、请求 ID、尝试次数、实际用量、停止原因及警告；块与原图保留页码、顺序和合法定位。当前元数据脱敏会过滤键名含 `token` 的字段，因此本模式将服务端归一化用量投影为 `usage.input/output/total/reasoning/cached_input`，另以 `unit="token"` 标明单位，缺失值保持未知；不直接写入整份供应商响应，也不放宽凭据过滤。使用已有 JSON 元数据，排除密钥、认证头及服务内部配置。日志只记录归属、页码、状态、耗时和用量，不输出文档全文或模型逐字回复。首版不建设逐页持久恢复或问答全文审计系统。

无法辨认的局部内容保留占位，待人工确认时文件级 `review_status` 记录为 `needs_review`。已启用的校对发生技术错误时记录 `incomplete` 并保留已识别正文。两种状态均暂停上传后的自动入库。清晰出版页眉页脚沿用排除规则，含无法辨认内容的页眉页脚转为独立文字块。校对模型未启用且没有未决项时记录 `not_requested`。正文页直接展示正文，未决项在“校对结果”查看。

任务中心由批量处理服务维护整体百分比。逐页识别按完成页数依次提交 `TaskContext.set_message`，模型请求继续共享并发额度。文件详情的“图片解析”页签在任务排队或运行期间重新读取附属结果，读到已发布结果或任务终态后停止。如果请求在读取旧附属结果后看到任务终态，服务端会重新读取同一正文版本的当前附属结果指针。 [文件详情源码](../../../../web/src/components/FileDetailModal.vue)

### 模型模式正文校对

一页识别完毕后，校对模型读取整页及左右区域的放大图，核对正文覆盖、阅读次序、数字、单位、上下标、公式、表格和引文。能明确识别的错误直接修改对应块，遗漏内容按原页位置补入。只把无法确认的差异、原图裁图和对应 Markdown 保存到人工校对记录。相邻页都完成后再检查页尾和页首，明确接续的段落或参考文献在合并时接起来。原文中印出的矛盾各自保留，混排页面中实际印刷的其他文章内容继续按原页保留。识别与校对复用现有共享模型请求配置。 [模型原图校对服务](../../../../backend/package/yuxi/services/pdf_recognition_review_service.py)

## 替代方案

| 方案 | 取舍 |
| --- | --- |
| 整本 PDF 一次请求并直接生成最终 Markdown | 难定位缺页与截断，失败时重做全文，不采用 |
| 新增一个伪 OCR 引擎承载通用模型识别 | 混淆 OCR 配置与用户自行选择的模型，并继续受到原有参数分支限制，不采用 |
| 模型逐页识别后再让模型重写合并全文 | 增加成本及数字、符号被改写的风险，不采用 |
| 只返回逐页 Markdown，再补一次模型找图片位置 | 中间协议较小，但多一次读取且可能丢失图文顺序，不采用 |
| 逐页返回有序内容块，程序确定性渲染 Markdown，复用独立插图任务 | 复用现有结果、存储、下载和入库链路，采用 |
| 通过相邻位置推断插图所属图注 | 图与图注交替排列时会漏绑，上下混排时也可能错绑。采用模型给出的同页明确引用 |
| 同期改造已有 OCR 正文校对体系 | 扩大新增模型识别之外的改动面；本提案复用原流程，暂不展开 |

## 风险

模型可能漏读或编造，而结构完整检查无法独立证明忠实度；清晰的小字、数字、上下标、双栏及跨页表格都需要真实样本验证。不设置单页时限时，慢请求持续占用共享槽位；运行仍受既有取消和任务生命周期约束，不据此承诺速度和费用。插图框的语义正确性仍需目视核对；合法坐标只证明可安全裁取。

首版只扩展 PDF，OCR 正文校对适配暂不展开，也不自动排除原文件中夹带的其他论文。识别模型收到的是真实页面图像，数据传输目的地由已选择的模型供应商决定。保存的文档产物继续受知识库权限约束。现有工作区中并行修改的代码在实施前需重新核对，不能把本提案当成已经完成的行为。
