# 实验结构化按完整记录提取和归并

状态：proposed
类型：bug-fix
Owner：backend/package/yuxi/knowledge/structure.py

## 问题

原流程先提取独立事实，再让一次全文请求返回卡片与事实 ID 的关联。实际任务已保留 220 条有出处的事实，其中 127 条是条件或结果，其余为样品、方法等组装材料。全文关联耗时 426 秒，返回的 14 个关联条目均未通过校验，最终发布 0 张卡片。截图、最终响应和汇总日志没有提供具体拒绝原因。

## 提案

### 实现方案

Paper 入库后的抽取模型按原文批次直接返回制备或测量记录，每条带样品与字段的原文引用。Worker 校验来源和表格交点，将通过校验的记录按原样品名称合并为机器草稿。单批输出格式失败仍可重试一次，其他批次的记录照常进入草稿。识别到明确的方法或结果章节时，排除引言、参考文献和出版附属栏目，优先处理本论文实验。全文模型关联请求由逐批记录提取替代。

批次使用现有[文档模型执行器](../../../../backend/package/yuxi/services/pdf_model_execution.py)和「文档模型请求并发数」。正文校对、插图和实验结构化的请求在同服务端点和模型上共享 Redis 租约。每篇论文在配置上限内发起请求，按原文批次顺序验证并归并响应，任务取消时收敛已启动的批次。日志分别记录准入排队和实际调用耗时。

只含样品名的候选不单独建卡。样品名、指标名与方法名属于组装材料，未能明确归属的条件或结果才进入候选展示。页面把已组装记录与候选分开，并对零卡片结果给出对应说明。机器草稿、版本绑定与正式问答的人工确认边界沿用现有约定。

## 替代方案

放宽全文关联 schema 可减少格式错误，仍保留单次请求的依赖。按样品对全文事实再发起多次关联可以隔离失败，但重复传输事实且增加请求数。按原文批次直接组装能使用模型当前看见的实验上下文，并让明确的记录独立发布。

实验结构化专用并发配置会让校对和结构化各自占满同一模型服务。共用现有额度能统一限制实际请求，设为 1 时所有批次继续串行。服务端点与模型均按现有规则分配额度。

## 后果

表格坐标校验与精确原文回填继续生效。跨段或跨批关系缺少明确局部证据时，留作候选。按样品归并合并卡片容器，每条测量仍独立保存。采用现有 JSON 结果与页面入口。
