# 实验批次按实际容量校验模型响应

状态：proposed
类型：bug-fix
Owner：backend/package/yuxi/knowledge/structure.py

## 问题

模型连续两次返回可解析 JSON，顶层列表条数超出提示里的建议数量。列表约束导致程序拒绝整批，已返回的有效记录无法逐条校验。同一任务也有成功解析却返回空记录的批次，旧日志只记录成卡数量。

## 提案

### 实现方案

抽取模块在提供给模型的 schema 中保留制备、测量和候选的建议条数。实际响应在正文大小上限内逐条校验，复用已有事实、卡片及卡内记录上限。模型明确报告省略记录时，仍标记该批未完成。嵌套字段及出处校验继续保护单条记录。其他 JSON 或结构错误沿用现有重试次数。

批次日志记录原文行范围、模型返回的各类条数和最终入卡数。提示明确说明一条记录可以独立返回，以便在其他记录缺少证据时保留已明确的制备和测量。

## 替代方案

要求模型再次生成同一批次会增加推理时间，且已出现连续违反相同条数限制的情况。截取列表前缀会舍弃尾部可校验的事实。让完整响应在现有资源上限内逐条校验可以保留已提取记录，并继续执行原有取值和归属规则。

## 后果

完整响应可以超过提示中的单批建议条数。正文大小和结果容量仍然有界。成功解析的空列表表示本次响应未给出记录，日志可以定位输入范围及是否有候选。
