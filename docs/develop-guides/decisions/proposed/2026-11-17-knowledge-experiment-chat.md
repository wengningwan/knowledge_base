# 知识库实验卡片与原文问答

日期：2026-11-17

状态：proposed

类型：feature

Owner：backend/package/yuxi/services/knowledge_paper_service.py

运行时 Context 拥有知识库 Skill 的加载，知识库工具拥有当前权限检查，结构化 repository 拥有实验记录及用户修改，聊天拥有来源预览。

## 问题

用户需要直接提问，由系统从已启用知识库查找相关论文，结合实验卡片和原文回答样品制备、实验条件与性能问题。实验卡片生成后即可使用，用户编辑覆盖原抽取值；“草稿”不构成问答准入限制。逐次选择论文会增加不必要操作，也会限制正常的知识库检索。

## 提案

### 实现方案

运行 Context 正常解析用户权限与 Agent 已启用知识库。存在可用知识库时，为本次运行选择并预加载 `knowledge-base` Skill，经现有 Skill repository 再次解析授权与依赖；Agent 的持久配置保留。普通聊天、恢复及子 Run 使用同一准备入口，不增加请求范围字段、论文选择器、数据表或运行状态。

知识库 Skill 拥有直接提问的操作顺序：按问题关键词调用既有 `query_kb`，将命中按 `(kb_id, file_id)` 去重；涉及实验时读取候选论文的当前记录，必要时打开或定位原文，再使用工具返回的出处组织回答。不同论文的样品、条件和结果分别保留，不拼接成一个已实现实验。未命中不表示全库不存在资料，继续检查其他相关的已启用知识库，资料不足时明确说明。

`read_paper_experiments` 复用当前正文指纹检查和实验记录投影，合并人工修改后按样品及分页返回有效记录、证据、出处和修订号。生成记录直接可用，不缓存卡片值，不用机器 JSON 覆盖人工值。已排除记录只返回不含旧值的身份，Skill 指示不得通过原文重新补回；尚未采用的候选不进入有效记录。部分完成、缺失及过期状态保留，卡片为空不等于原文未报告。

知识库工具每次执行重新解析用户读取权限，并与本次 Agent 已启用范围求交。实验读取另在 repository 校验文件归属和当前权限。HTTP read 依赖以已登录身份加知识库 READ 权限执行，manage 依赖继续要求管理员和资源管理权限；知识库详情的敏感配置继续按有效权限脱敏。来源保留工具返回的知识库、文件、版本及证据身份，前端复用文件详情与来源列表；文件预览读取继续经过后端授权。分页的实验读取工具与现有原文读取工具一样保留原始工具结果，不转存沙盒，避免失去来源列表。原有向量、关键词、混合与图增强检索保持现有实现，不增加新的召回模式。

知识库查询投影从 Milvus 已返回的片段读取参与召回的来源，图谱命中写入片段元数据，随既有工具结果保存。普通对话的「来源」汇总本轮返回的片段。结果含图谱命中时，回答下方的「来源」及对应文件和片段显示「图谱辅助检索」。同轮多次返回同一片段时，来源去重保留图谱命中标记。

不开发独立的多论文路线比较、全库结构化数值筛选、实体合并、自动曲线取点或新的问答页面。持久化内部 draft 状态保留兼容，已完成抽取在问答中返回 available。

## 替代方案

| 方案 | 取舍 |
| --- | --- |
| 每次先选择论文并传递专用范围 | 用户必须提前知道答案在哪，且增加 UI、请求与运行协议，不采用 |
| 只检索原文回答 | 不能使用用户已修改的实验记录，不采用 |
| 把全部实验记录重建成另一套搜索索引 | 增加同步与维护成本；当前先复用原文召回找到候选论文，暂不采用 |
| 先检索相关论文，再读取当前卡片与原文 | 复用现有检索、Skill、工具及预览，采用 |
| 从本轮返回的原文片段显示图谱参与 | 复用聊天来源入口与真实召回记录，采用。仅显示开关状态无法证明本轮已命中 |

Inspected：文件读取、rg 符号检索、git diff 及独立静态审阅覆盖自动加载、工具注册、权限、记录投影、来源预览与选择机制移除。静态证据不表示真实链路通过。

本机只进行文件读取、符号检索和静态审阅，不启动应用，不运行测试、构建、lint、工程契约脚本或 diff 检查命令。真实 HTTP、PostgreSQL、Milvus、worker、模型与浏览器验收，以及保留静态检查均由用户在部署电脑执行。预期结果不表示实际通过。

## 风险

原文召回可能遗漏相关论文，尤其问题仅包含用户后加的名称或数值而原文没有这些内容时；本轮不承诺全库结构化穷尽检索。模型可能遗漏条件或错误解释，需要以真实问题核对工具结果和最终答案。原文及卡片属于资料，不应成为系统或工具操作指令。历史回答保留生成时文本，编辑只影响新回答。
