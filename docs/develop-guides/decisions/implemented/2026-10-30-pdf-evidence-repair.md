# PDF 规则修复与问题驱动复核

状态：implemented
类型：feature
Owner：backend/package/yuxi/services/pdf_review_service.py

模型调用预算、完整块回执与日志部分由[完整复核与共享模型并发](2026-10-30-pdf-complete-review.md)取代；其他原文/附属版本机制继续有效。

## 问题

以字符串不一致为触发条件逐块调用视觉模型，把排版差异、出版水印与真实科学内容错误混在一起，增加模型请求和误报。原生文字层本身有字体编码问题，宽松摘句命中不能证明修订正确。

## 决策

### 实现方案

OXR 保持主识别器，现有 blocks 为正文权威结构。原生字符和位置形成区域证据，先做保护区、区域分类和可证明规则修复，再将少量未决问题交给有文档预算的文字或局部视觉复核。复用同事 pdf-md-quad-repair 2.7.7 的保护区、规则事务和证据回放思路，不执行其共享目录 CLI，不以其宽松指纹作为关键内容修改的最终依据。

模型复核限制实际请求、时间和共享并发，保留无法确认的结果。图片解释从主解析链路分离为 Durable Task，父任务发布正文时同事务创建子任务 intent；子任务只更新同正文 attempt 的独立 sidecar revision，不改正文或索引。MD 仍只包含论文原文图文，报告继续使用现有校对页签的数据通道，本期不设计新报告布局。

## 替代方案

继续全块视觉校对难以控制请求规模。仅用原生文字覆盖 OCR 会复制字体编码错误。把 skill 的人工规则生成和数秒重放视为完整自动修复，会把未经证实的性能描述带入产品。后台自由改写正文则会使已入库索引失去版本归属。

## 后果

本机按用户要求不启动环境或运行应用测试，模型效果和耗时需另一台机器验证。预算耗尽的项目必须标为未决，不能声明全部校对通过；也不能把减少报告条数当成准确度提升。两份不同论文报告用于回归，不直接作为同篇A/B的准确率数据。

静态检查范围为 Python AST、Vue 脚本 Node 语法和 Git 差异空白；运行测试、HTTP/MinIO/worker、浏览器和论文效果均 Not run。源码包含相应单元与真实 PostgreSQL 集成用例，必须在验证机执行后再判断行为和准确性收益。
