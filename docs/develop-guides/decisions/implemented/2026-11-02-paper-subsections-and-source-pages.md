# 论文小节与续句边界、来源 PDF 页定位

状态：implemented
类型：bug-fix
Owner：backend/package/yuxi/knowledge/chunking/paper.py

## 问题

论文解析结果可能把数字小节标题与正文放在同一行，或把跨页句子分成相邻段落。仅识别独立标题会丢失小节边界；按长度组合独立片段可能在半句话处产生检索边界。已经核对的 PDF 来源页需要可直接回查的入口。

## 决策

### 实现方案

Paper 在原 Markdown 坐标上识别独立和同行正文前的数字小节，区分标题范围与正文范围；同一小节、相同明确实验身份的相邻文字，仅在前段未结束且后段以英文小写续接时保留为一个证据单元。完整段落仍按现有长度目标组合，公式和图表继续独立保留完整证据。切分版本记为 paper_rules_v2；原文不被改写，所有范围可回读。

分块专用 PDF 页跳转由[正文来源与关联证据决定](2026-11-03-paper-related-evidence.md)取代；当前预览保留 Markdown 来源弹窗与普通原文件预览。

独立段落继续在同节按长度目标组合。正文图号和同小节的跨块检索补取由[正文来源与关联证据决定](2026-11-03-paper-related-evidence.md)拥有，图表间阅读顺序由解析链路负责。文末参考文献排除、正文引用标记保留及其他证据组织行为由[论文证据分块决定](2026-11-02-paper-evidence-chunking.md)说明。

## 替代方案

- 提高目标长度无法恢复漏识别的小节，也不能可靠避免相邻续句产生边界。
- 把整节放进一个块会降低定位粒度，扩大查询输入。
- 自动重写 Markdown 会改变原文指纹和坐标；这里保留来源字节，仅调整证据边界。
- 用未经核对的页码或另建下载链接会绕开现有来源和授权边界；复用原文件预览路径。

## 后果

数字小节和英文续句采用保守规则，无法替代 PDF 阅读顺序恢复。切分变更需重新入库才影响现有文件。PDF 页码只在现有解析版面精确匹配时存在；浏览器模拟 API 不证明真实入库集成。本机无 Docker，真实 PostgreSQL/worker/Milvus 回归仍需部署验证。
