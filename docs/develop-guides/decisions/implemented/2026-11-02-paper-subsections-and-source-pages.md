# 论文小节与续句边界、来源 PDF 页定位

状态：implemented
类型：bug-fix
Owner：backend/package/yuxi/knowledge/chunking/paper.py

## 问题

论文解析结果可能把数字小节标题与正文放在同一行，或把跨页句子分成相邻段落。仅识别独立标题会丢失小节边界；按长度组合独立片段可能在半句话处产生检索边界。已经核对的 PDF 来源页需要可直接回查的入口。

## 决策

### 实现方案

Paper 在原 Markdown 坐标上识别独立和同行正文前的数字小节，区分标题范围与正文范围；同一小节、相同明确实验身份的相邻文字，仅在前段未结束且后段以英文小写续接时保留为一个证据单元。完整段落仍按现有长度目标组合，公式和图表继续独立保留完整证据。原文不被改写，所有范围可回读；策略标记与唯一实现遵循[当前实现决定](2026-11-05-paper-single-implementation.md)。

ChunkPreviewPanel 仅为经当前来源指纹和坐标核对且具有真实页码的 PDF 来源提供打开按钮。FileDetailModal 复用现有授权原文件读取和 AgentFilePreview，向 PdfPreview 传入目标页；PDF 加载及页面渲染完成后定位。无页码、陈旧来源和非 PDF 文件不提供猜测跳转，文件切换清除目标页。

独立段落继续在同节按长度目标组合，正文图号和多式推导的跨块检索扩展、图表间的阅读顺序恢复属于独立问题。文末参考文献排除、正文引用标记保留及其他证据组织行为由[论文证据分块决定](2026-11-02-paper-evidence-chunking.md)说明。

[连续性与处理边界决定](2026-11-04-paper-evidence-continuity.md)补充跨浮图的明确续句与同行父子标题识别，并更新图表上下文；来源 PDF 页定位继续使用经核对的同次解析范围。

## 替代方案

- 提高目标长度无法恢复漏识别的小节，也不能可靠避免相邻续句产生边界。
- 把整节放进一个块会降低定位粒度，扩大查询输入。
- 自动重写 Markdown 会改变原文指纹和坐标；这里保留来源字节，仅调整证据边界。
- 用未经核对的页码或另建下载链接会绕开现有来源和授权边界；复用原文件预览路径。

## 后果

数字小节和英文续句采用保守规则，无法替代 PDF 阅读顺序恢复。切分变更需重新入库才影响现有文件。PDF 页码只在现有解析版面精确匹配时存在；浏览器模拟 API 不证明真实入库集成。本机无 Docker，真实 PostgreSQL/worker/Milvus 回归仍需部署验证。
