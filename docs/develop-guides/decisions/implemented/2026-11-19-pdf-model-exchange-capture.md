# 按文件采集 PDF 模型请求与回复

状态：implemented
类型：feature
Owner：backend/package/yuxi/services/pdf_model_execution.py

## 问题

常规 PDF worker 日志记录请求、大小、耗时和安全错误类别。现有解析产物保留最终正文和校对结果，无法复原首轮识别、结构校对、原文疑点复核和插图请求各自的输入与模型回复。

## 决策

### 实现方案

部署操作员在执行解析的 worker 运行目录为特定文件建立启用标记。共享 PDF 模型执行器按文件、解析尝试和请求编号采集实际提示词、正文、按序的图片字节，以及业务格式校验前的可见回复及其文字分段。独立插图任务沿用正文解析的尝试标识。模型调用收敛、共享槽释放后有界保存记录，操作员按[采集步骤](../../../advanced/document-processing.md#临时采集某个文件的模型交互)从 worker 复制。

## 替代方案

- 把原文和模型回复放入常规日志。所有已采集日志的读者会获得源文档，图片也会大幅膨胀日志。
- 在知识库 Doc API 增加下载入口。该能力用于单文件故障定位，部署操作员使用运行目录即可取得，不增加业务数据或浏览器权限面。

## 后果

标记仅作用于当前 worker，移除标记后停止登记新采集。目录包含导入文档的原图和文字，通过部署权限访问。Worker 替换前需复制诊断文件；多 worker 部署需要分别在参与解析的容器采集。常规日志继续记录请求大小和安全分类。采集 I/O 出错或达到等待上限时记录请求编号和安全类别，主流程沿用实际模型调用的结论。进程中断可能留下缺失的采集，超时的写入也可能稍后完成。
