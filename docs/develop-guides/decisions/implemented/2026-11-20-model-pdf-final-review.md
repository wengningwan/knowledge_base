# 模型 PDF 在跨页接续后终审成稿

状态：implemented
类型：feature
Owner：backend/package/yuxi/services/pdf_recognition_review_service.py

## 问题

发布前的程序核对将换行断词、页眉页码和已经保留的表格片段当成待确认差异。同栏定位也可能缺少完整上下文，给出删除正确参考文献页码的候选。成稿中可定位的漏字和引文差异需要继续处理。

## 决策

### 实现方案

跨页接续完成后，识别服务先渲染一份 Markdown 成稿快照。每页终审复用已配置的正文校对模型及其并发限制，提供这一页的原图和疑点定位。成稿不超过 24,000 字符时提供全文，超过时提供当前页、相邻页接续文字和章节线索。

原文比对只生成同栏、前后能定位的局部候选，排除换行断词和未对齐的页边或公式表格文字。最终原图校对确认的候选通过校验后写回。模型可引用相邻字句支持保留成稿，引文号码仍有冲突时交人工确认。同页块间位置仍由逐页复核处理，成稿终审检查段内文字、遗漏正文和跨页接续，接续复核提供前后两页原图。模型另外发现且能定位的差异可以进入人工校对。

已启用的终审部分看不清或请求失败时，保留已定位的候选，在校对结果顶部列出未完成的页并暂停自动入库。主动留空正文校对模型时，提示未执行模型终审，并按现有待确认项决定是否暂停自动入库。

本决定取代[旧的成稿程序核对](2026-11-19-model-pdf-final-source-audit.md)生成宽泛人工待办的方案，并沿用其中的跨页接续人工处理。

## 替代方案

- 保留程序输出的所有差异供人工确认。缺少定位的结果和排版差异会淹没有证据的文字差异。
- 整篇论文用一个不限大小的模型请求检查。短文较直接，较长的文档无法可靠覆盖每一页。

## 后果

终审增加原图和正文模型请求，耗时和 token 随页数及文档长度增长。程序证据不足的内容仍可通过模型看图发现，覆盖情况以真实样例回读为准。
