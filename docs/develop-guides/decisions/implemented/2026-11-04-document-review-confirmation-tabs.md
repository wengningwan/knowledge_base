# 校对结果按确认任务展示分类

状态：implemented
类型：simplification
Owner：web/src/components/knowledge/DocumentReviewPanel.vue

## 问题

校对结果把人工待核对与复核未完成拆为两个入口，用户需要反复切换才能处理全部待确认问题。

## 决策

### 实现方案

校对面板只提供“待确认”和“已确认”。待确认使用原问题分组的 attention 与 incomplete 的并集，每个原问题只计一次；已确认仍要求组内所有记录均有人工确认。优先展示待确认；无待确认且存在已确认时展示已确认，否则显示待确认空状态。状态名称中的“人工已确认”统一为“已确认”。问题列表标题仅显示“问题列表”，列表状态行、详情状态标签和问题级复核未完成提示条不显示；详情保留问题原因、出版元素及关键修改标签，没有标签时不渲染标签行。文档级汇总提示、自动入库提示、分片选择中的机器状态、筛选计数与保存错误继续表达各自结果。后端记录、分组身份和保存接口保持现有契约。

## 替代方案

保留五个分类会延续用户切换成本；只隐藏按钮而保留自动选择全部记录或空态入口，会让页面仍进入不可见分类。直接修改底层分组状态会扩大其他消费者的语义变化，筛选并集由面板负责。

## 后果

系统已修改和普通已核对记录不在两个任务分类中展示；机器原始记录仍保留。该变更为局部且完整的界面简化，需求已明确分类及名称，无待裁决的持久状态或兼容风险，直接记录 implemented。

## 验证

组件运行测试断言仅有两个分类、合并去重、分页可达、仅失败记录默认可见、空态没有全部记录入口、人工确认后归入已确认。恢复五分类实现时测试在分类名称和数量断言处失败。执行命令：`node --test web/test/unit/document_review.test.js web/test/unit/document_review_runtime.test.js`。

旧能力不存在：分类按钮与空态不再提供系统已修改、全部记录或独立复核未完成入口；列表标题计数说明、列表状态行、详情状态标签及问题级复核未完成提示条均无渲染节点。

重新引入条件：用户提出独立查看机器处理历史的明确需求，再评估对应入口。

展示简化的组件断言核对上述节点缺失，同时保留失败问题的待确认归类、文档级提示、问题原因、出版元素和关键修改标签。恢复相应节点会使缺失断言失败；用例未运行（Not run）：本机约定仅修改代码与文档，lint、unit、build 和真实页面效果均待另一台电脑验证。该简化直接更新现有决定，删除范围由用户截图明确，不涉及新的持久化或兼容取舍。
