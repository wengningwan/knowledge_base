# 知识库配置提供聊天模型选择

状态：implemented
类型：bug-fix
Owner：web/src/views/DataBaseInfoView.vue

## 问题

实验卡片任务冻结知识库现有的 `llm_model_spec`，模型缺失时显式失败。知识库详情的配置表单没有该字段，管理者无法通过页面完成任务要求的设置。

## 决策

### 实现方案

Milvus 知识库的“配置 → 基础信息”提供“知识库聊天模型”，复用现有聊天模型选择器。打开表单回显当前知识库值，保存沿现有更新 API 写入 `llm_model_spec`；清空显式传 `null`，其他类型不提交该字段。提示文字链接现有模型供应商页面，说明本地模型需先添加并启用，保存后可重试失败卡片任务。worker 的缺失模型提示指向同一设置路径。

本修复仅补齐已有后端字段的用户入口，不新增模型配置、任务、存储或 fallback，因此直接记录为 implemented。API 权限和数据库更新语义由现有知识库更新链路拥有。

## 替代方案

要求用户直接调用更新 API 会继续留下页面操作断点。回落系统默认模型会改变实验任务的显式模型选择及本地部署承诺，故保留知识库级选择。

## 后果

新创建和既有知识库都可在详情页设置模型。已创建任务仍使用冻结值；失败重试创建新版本并读取已保存的知识库模型。设置不保证 endpoint 位于本地，部署者应选择自己部署的服务。

## 验证

Inspected：核对选择器的 chat 类型、事件和清空值，表单回显、提交与后端 `model_fields_set` 更新语义；重试读取当前 `kb.llm_model_spec`。部署报告的缺失模型异常用于定位入口缺失，不作为修复通过证据。

Not run：按本机约定，未启动程序或运行测试、lint、构建、工程验证脚本，页面与真实持久化未验证。

人工验收：Milvus 详情打开配置，选择本地聊天模型保存，重新打开后应回显同一模型；回读知识库 API 的 `llm_model_spec` 与所选值一致。进入失败文件的实验卡片并重试，新 revision 使用该模型。清空并保存后重新打开应为空，新任务继续明确报告缺失模型；关闭弹窗未保存不能改变配置。Dify/Notion 表单不显示或提交该字段；无管理权限用户不能更新。检查模型列表加载、错误、空态与明暗主题。
