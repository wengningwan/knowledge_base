# 分块界面默认选择 Paper

状态：implemented
类型：feature
Owner：web/src/utils/chunkUtils.js

## 问题

论文入库需要反复手动选择 Paper，策略列表中的位置也增加了查找成本。

## 决策

### 实现方案

前端新建知识库、上传自动入库和首次入库表单默认选择 `paper`，首次入库不采用上传时从知识库继承的策略。共用策略列表把 Paper 排在首位，其余策略保持相对顺序；文件配置中的“沿用知识库默认”放在策略列表末尾，选择后请求省略分块策略字段。重新入库回显文件已保存的策略，缺少策略时使用 Paper，用户可以手动切换。前端的默认值和选项顺序不修改后端省略参数时的解析规则，也不重写既有文件或知识库配置。

`web/src/utils/chunkUtils.js` 拥有前端默认值，`web/src/composables/useChunkPresetOptions.js` 拥有选项排序，`web/src/components/ChunkParamsConfig.vue` 拥有沿用选项的位置。上传与文件入库入口把默认值写入表单；单文件待入库状态 `parsed` 使用 Paper，失败重试和重新入库优先回显已保存策略。

## 替代方案

只调整排序仍需每次手动选择。强制所有重新入库操作切换为 Paper 会覆盖用户保存的其他策略，因此保留已保存策略的回显。

## 后果

新配置提交时携带 Paper，用户选择其他策略或沿用知识库默认后按其选择提交。分块算法和解析流程不变。
