# 验证规范

本项目按用户决定移除第一方自动化测试套件及其命令、依赖和 CI 接线。变更通过源码审查、静态检查以及部署电脑上的人工操作验证；需要恢复自动化测试时先取得用户明确要求。范围与代价见[移除项目自动化测试套件](./decisions/implemented/2026-11-04-remove-project-test-suites.md)。

本机仅修改代码与文档，不启动程序，不执行测试、构建、依赖重解算或验证脚本。以下运行检查由用户在另一台电脑手动完成，Agent 只记录实际收到的证据。

## 按改动选择验证

| 改动面 | 人工验证观察边界 |
| --- | --- |
| 业务计算和文本处理 | 使用有明确预期的代表输入、空值和边界输入，核对完整输出 |
| API、权限和持久化 | 通过真实 HTTP 操作，以不同权限身份核对允许与拒绝结果，并回读数据库或对象 |
| Run、FIFO、SSE、恢复与沙盒 | 走实际请求链路，观察顺序、取消、断线恢复、最终状态及文件产物 |
| 前端交互 | 在真实页面操作，检查核心流程、空态、错误、浅深色与适用的响应式宽度 |
| 文档和导航 | 核对相对链接和目标内容，在部署电脑完成文档构建 |
| 安装与发布配置 | 在部署电脑核对锁定依赖安装、镜像构建和启动结果 |

每个输入校验或状态限制都保留可人工复现的负向案例：说明如何制造非法输入或恢复目标缺陷，以及预期拒绝结果。记录必要的前置条件、操作和观察结果，避免用日志关键词、HTTP 200 或完成提示替代最终事实。

## 保留的检查命令

工程契约检查只读取当前源码、决策、约定与剩余 workflow：

```bash
python3 scripts/verify_engineering_contracts.py
git diff --check
```

代码风格、构建、供应链审计继续由各自入口维护：

```bash
make lint
docker compose exec web pnpm run lint:check
docker compose exec web pnpm run build
cd docs && pnpm run build
make audit-dependencies
make audit-licenses
```

构建成功只证明可构建，静态契约检查只证明其覆盖的引用与边界；二者都不能替代真实业务操作。`/api/system/health` 表达进程存活，`/api/system/ready` 表达接流量前置条件，业务正确性仍需核对实际结果。

## 证据和交付

- `Passed`：操作或命令实际执行成功，且结果已核对。
- `Inspected`：只读检查了源码、配置、文件或已有材料。
- `Not run`：未执行，必须说明原因、未验证范围和风险。
- `Inferred`：仅从间接材料推断，不能作为直接通过证据。

交付说明列出实际命令或人工操作、预期与观察结果、环境、外部服务和缺失证据。独立 Reviewer 核对完整需求、diff、Owner、复杂度和未验证范围，不能以静态 Review 代替运行结果。

## 历史材料

历史 decision、postmortem 和 changelog 中的测试文件名、命令及结果仅保留当时的证据与背景；相关套件、样本和专用性能工具已移除，历史命令不可作为当前执行入口。知识库评估、模型连接检查、生产健康检查和运行时校验属于业务能力，继续保留。
